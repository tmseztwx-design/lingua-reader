# 管理员配号、强制登录、不开放注册

本次替代内测码与临时免码方案。前端主站和管理入口均强制登录，普通账号不能进入控制台。控制台创建/搜索用户、随机生成或指定密码、重置密码、停用/启用账号、查看最近管理记录。用户在其他设备登录同一账号即可访问同一书库。

除 localhost / 回环地址开发外，登录只允许通过 HTTPS 页面提交密码。

## 数据和权限结构

- `auth.users`：Supabase Auth 保存、哈希和验证密码，不在自建表或浏览器中保存明文密码。不使用邮箱注册流程；每个受管理账号使用随机内部邮箱身份。
- `scribe_accounts`：用户名、显示名称、角色（唯一 owner / member）、唯一书库、停用状态及凭证版本。只有服务端可读写，普通注册出的 Auth 身份没有此表记录、没有书库权限。
- `scribe_account_sessions`：12 小时应用会话，数据库只保存令牌 SHA-256。浏览器按标签页保存会话，刷新保留，关闭标签页或退出后需要重新登录。每个接口通过数据库检查过期、停用与凭证版本，不信任客户端角色或书库标识。
- `scribe_login_limits`：数据库原子限流，单账号每 15 分钟 30 次、项目总计 600 次，包含成功尝试。公网发布仍建议配置网关 IP 限流/WAF，以免有人恶意消耗全局限额。
- `scribe_account_audit`：账号创建、停用/恢复、重置密码等事件，不保存密码和令牌。
- 文献、卡片、原件、识别队列仍使用现有书库和私有桶，不复制、不重建已有用户数据。账号迁移只做关联。

停用、启用和重置密码都会撤销旧应用会话；启用不会复活旧会话。普通账号每次 API 请求都受到校验；闲置页面每分钟重新验证一次。已打开的缓存无法远程擦除，已签发的原件 URL / 上传 URL 在到期前也不一定能立即撤销，不能承诺消除已下载副本。

最高管理员拥有账号管理最高权限，但不是免密入口，不能通过用户管理接口停用自己、重置自己或新建另一个 owner。首次管理员使用服务器安全配置初始化，忘记管理员密码需在受控的 Supabase Auth 管理环境重置该管理员 Auth 身份的密码并撤销 `scribe_account_sessions`，不是通过公开“找回密码”接口。

## 本机数据隔离和旧数据保留

`storage-vault.js` 在验证登录后才允许旧阅读脚本启动，并将文献、卡片、同步状态、词库缓存、复习会话等存入 `account:<id>:` 独立命名空间。跨标签页广播也带账号作用域。待上传队列按稳定账号标识隔离，不再自动接收未归属的旧队列。退出不会删除个人缓存，但其他账号不使用这些缓存。

旧的 IndexedDB、旧书库同步码和未上传文件均保留在原位置，不自动归给第一个登录账号。最高管理员在学习空间可使用“导出本机旧版学习数据”，再从当前账号的设置导入 JSON；该 JSON 不包括图片/PDF 原件。旧云端书库可在控制台“创建账号 → 绑定已有旧版云端书库”输入旧同步码，原文献/卡片/页序原地保留；同一书库禁止分给两个账号。不要为解决绑定问题清空本机数据库。

这些是同一浏览器内的逻辑隔离，不是浏览器缓存加密。共享电脑仍应使用独立 OS / 浏览器配置文件，并防止他人访问开发者工具和磁盘。

## 必须在当前 Cloud 执行的部署步骤

当前代码已更新，本地登录页可预览；**本次没有 Enter Cloud 部署凭证，未声称迁移或云函数已经在实际 Cloud 上生效，也没有创建实际管理员凭据。**

1. 备份现有 Cloud 数据。先按历史迁移顺序完成既有上传/同步迁移，再执行 `supabase/migrations/20261022180000_managed_accounts.sql`。这是新增账号表、函数及扫码通道版本列，不删除旧文献。
2. 在当前 Cloud 的服务端安全设置中配置 `SCRIBE_ADMIN_USERNAME`（默认 `admin`，3–32 位英文字母/数字等）和 `SCRIBE_ADMIN_PASSWORD`（至少 12 位，UTF-8 不超过 72 字节；建议使用长随机英文/数字/符号密码）。不要将密码发到聊天、写进前端、提交 Git 或放进 VITE_ 环境变量；不要使用文档示例作为实际密码。现有管理员密码达到长度要求时可沿用它完成首次初始化。
3. 在托管 Cloud 的 Auth 配置关闭公开用户注册、匿名登录及不使用的 OAuth/OTP 自助创建入口。`supabase/config.toml` 的关闭注册配置主要针对本地 CLI，不能冒充修改了托管 Cloud 设置。即使托管 Auth 误开注册，新身份也不能获得应用书库权限，但仍须关闭以减少滥用。
4. 运行 `pnpm bundle:functions`。部署七个函数：`scribe-accounts`、`scribe-library`、`scribe-mobile-upload`、`scribe-study`、`scribe-beta`、`scribe-queue`、`scribe-ocr`。必须同步更新共享鉴权后的各个函数；`scribe-beta` 应返回 410，`scribe-library create` 始终 403，旧同步码不能继续直接授权。
5. 维护窗口内原子切换前端与后端；不要只发登录界面而保留旧 API。运行 `pnpm build` 后发布主站、`/?admin=1` 和 `/admin.html`，核对正式 HTTPS 地址及 worker/cron。确认 service_role 和管理员密码未进入构建文件。
6. 在控制台用安全配置中的管理员账号密码首次登录。服务端验证后初始化唯一 owner，再通过控制台生成普通账号；凭据只显示一次，列表不提供查看原密码功能。请通过安全渠道交付用户，遗失则重置。
7. 验收：无登录拒绝书库/识别接口；普通用户不能调用账号管理；账号 A/B 互不见数据；同账号跨设备共用书库；停用/重置后旧会话与旧 QR 无效；过期会话要求登录；旧云端书库绑定后文献/卡片/页序不变；手机通过短时 QR 只可向当前批次上传。

`server.mjs` 的旧免登录本机 API 默认关闭，因此不能用其本地 OCR 旧协议绕过账号。该路径尚未迁移为独立账号后端；当前账号方案仍使用 Enter Cloud。

## 验证依据与剩余边界

测试使用真实 PostgreSQL 兼容 PGlite 执行迁移/权限/会话撤销，并模拟 Supabase Auth 的账号 API；不能替代实际托管 Auth、网络、流量额度、微信扫码和生产配置验收。未接入真实 Cloud 前不能生成可实际登录的生产账号。

采用官方服务端 [Auth 管理创建用户](https://supabase.com/docs/reference/javascript/auth-admin-createuser) 接口，不将 service_role 放到客户端。注册配置的托管与本地边界参见 [Supabase Auth 配置](https://supabase.com/docs/guides/auth/general-configuration)及 [CLI 配置说明](https://supabase.com/docs/guides/local-development/cli/config)。视觉参考及适配记录见 `DESIGN.md`。
