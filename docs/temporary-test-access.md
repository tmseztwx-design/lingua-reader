# 临时免内测码测试（2026-10-22）

> 此方案已被同日的账号管理重构取代。当前必须登录，不再支持临时免码建库开关。请使用 [账号系统部署与迁移](managed-accounts.md)，不要按下文的历史步骤重新开放匿名建库。

`supabase/functions/_shared/access-policy.ts` 的 `BETA_REQUIRED = false` 是本次临时开关。前端与可部署的 `scribe-library` 使用同一份开关，不删除内测码系统。

## 行为与数据保护

- 导入页改为“无需内测码，直接体验”，不再要求兑换内测码。
- 已有书库钥匙、内测会话、文献、卡片及待上传文件保持不变。
- 无书库的设备向服务端申请独立书库，拿到服务端实际签发的随机凭证后才同步；并发请求合并，失败时限频重试。
- 不使用共用书库、万能内测码、伪造会话或随机但未注册的钥匙。其他书库、私有文件、OCR worker 和管理后台仍按原来的凭证鉴权。
- 服务端 `SCRIBE_BETA_REQUIRED=true` 可强制关闭匿名建库；只有明确的 `false` 才可覆盖打开，拼写错误按关闭处理。客户端不能覆盖这个设置。

## 部署边界

本地 Vite 更新并不等于 Enter 云函数已部署。本次本地页面实测：旧的云函数仍返回 403。当前没有 Enter 的部署凭证，因此未更改实际 Cloud 配置或数据库。

要测试云端建库、上传与同步，需运行 `pnpm bundle:functions`，在当前 Enter Cloud 部署 `supabase/functions/scribe-library/index.ts`，确认服务端变量没有强制设为 `true`。不需要为了这个开关迁移数据库。上传 v2 另需既有的上传完整性迁移，不能把解除准入误当成完成上传升级。

在部署完成前，界面会明确提示“云端仍在使用旧的准入设置”，不会假报同步成功；本地已有文献、学习与复习仍可测试。部署后在设置中点“立即同步”重试。

这是临时测试配置：发布到公网后，访客无需内测码即可新建书库并使用项目额度，不宜作为正式的用户注册和配额管理方案。

## 恢复

收到恢复指示后，把同一文件改回 `BETA_REQUIRED = true`，运行 `pnpm bundle:functions` 与 `pnpm build`，发布前端并重新部署 `scribe-library`。同时移除服务端 `SCRIBE_BETA_REQUIRED=false`（或改成 `true`）。不要删除用户凭证、会话、书库或学习数据。

恢复会阻止新的免码建库并显示原内测码入口；与原系统兼容，已持有有效书库凭证的设备不会被强制注销。
