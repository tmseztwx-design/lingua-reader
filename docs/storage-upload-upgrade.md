## 本次解决的瓶颈

| 旧问题 | 新实现 |
| --- | --- |
| 串行上传、断网重传整份大文件 | 电脑最多 3 路、手机最多 2 路；≥6 MiB 使用 TUS 6 MiB 分片、HEAD 核对偏移续传；小文件最多 4 次有退避的重试 |
| PDF 一次读入整份，所有 JPEG 留在内存 | PDF 通过 File 分段读取；每生成一页就等 IndexedDB 保存，随后才渲染下一页；UI 仅保留文件元数据 |
| 上传速度改变页序、漏页却可点完成 | 上传前一次性提交不可变清单；数据库锁定批次，唯一页序；完成时校验所有预期页面和 PDF 原件分片均送达 |
| 页面刷新后丢队列 | 文件二进制、排序、云批次和续传地址保存在 `scribe-upload-staging`；按书库/手机 token 隔离；成功后清暂存 |
| 逐个进度刷新重画数百行 | 仅更新对应行；列表限制高度，离屏行跳过布局；阅读缩略图延迟加载 |
| 每传一张就全表统计 | 预登记时批量插入，最终提交时统一统计，避免批量导入的 O(n²) 查询 |
| 每 15 秒反复传整库 OCR 文本和签名链接 | 条目修订号与文献版本协商，仅回传变动项；文献进度与 OCR 正文分离；签名 URL 按需续期 |
| 超过默认 1000 行导致漏页 | 所有文献页面/原件/书库主读取显式按 500 行分页；签名和删除按小批处理 |
| PDF 拆页后完整原 PDF 未单独保存 | `scribe_source_assets` 保存逐字节原 PDF，按 32 MiB 分片；阅读区「下载原始 PDF」按片序还原，可流式写盘 |
| 长文翻译只取前 80 段，阅读区后文消失 | 原文段落完整保留；翻译单次最多 80 段且限制提示长度，缺译不会删除正文 |
| 多设备累计时间/复习数没同步 | 每书库/设备累计计数器，重复请求幂等、离线增量合并；新设备读取已有总量不会重复计算历史 |
| 查词语境使用全站共享明文缓存键 | 加入书库归属，缓存键按书库和语境 SHA-256；不再命中其他书库的语境缓存 |

## 数据归属与新结构

- `scribe_libraries`：书库租户与统计基线；同步凭证仅保存哈希。内测阶段仍是凭证体系，不等同于完整邮箱账户、找回或 MFA。
- `scribe_cloud_sessions`：书库所属上传批次，确认清单、预期页数、完成/删除时间、文献更新时间。
- `scribe_cloud_files`：识别页，每页位置唯一；原页对象路径、OCR 原文与逐段译文、后台任务租约。正文不再重复写进书库进度条目。
- 新增 `scribe_source_assets`：原 PDF 分片；包含原名、原大小、分片数量和序号，归属批次，通过批次归属书库。**旧版本已经丢掉的原 PDF 无法凭空恢复**。
- `scribe_library_entries`：可修订的文献信息/进度、学习卡、偏好；保留修订冲突与删除墓碑。
- 新增 `scribe_study_counters`：`(library_id, device_id)` 主键，累计时长和复习次数；服务端单调合并。
- `scribe_word_cache`：新增 `library_id`，新记录书库隔离。旧的未归属缓存保留但不再命中，不删除用户卡片。
- 新表 RLS 开启，撤销 `public/anon/authenticated` 访问，只允许服务端角色；私有桶不改为公开。签名上传令牌只针对一个对象。

## 明确的边界

1. 本次实测存储 TUS `OPTIONS` 返回 `Tus-Max-Size: 52428800`（50 MiB），不是 UI 原先写的 100 MB。大 PDF 使用 32 MiB 原件分片，不需要购买新服务器来绕过这个限制。项目总容量、带宽和付费配额仍以 Enter 套餐为准。
2. 单批上限 2000 页、文件与原件合计 5 GiB。不是无限数量承诺；超限在传输前提示，不能静默跳页。普通单个对象不超过 50 MiB。超大 PDF 在低内存手机上仍建议电脑导入；PDF.js Worker 本身也需要解析内存。
3. 浏览器选取器回传的初始顺序可能受系统影响，因此以用户确认后的排序列表为准。微信的单次选图限制不是网页能够解除的，可多次选图加入同一队列。
4. 上传中要保持手机页面可运行。iOS/微信切后台可能暂停网络；返回同一个浏览器/同一地址后续传。只有「全部送达」之后，识别才能在关闭页面时由云后台继续。
5. 上传通道原有 24 小时有效期保持不变。超过有效期不能继续提交，要重新建立通道。已完成文献不因 token 到期而被清理。未完成且过期的批次，额外保留 30 天后清理；最近删除仍保留 30 天。
6. `HEIC/HEIF`、旧 `.doc` 没有可用的云端识别器，新版会在上传前明确拒绝（不再传完才失败）。请转为 JPEG/DOCX/PDF。原生拍照入口仍保留。
7. 原 PDF 下载在 Chrome/Edge 可直接按分片写盘；不支持 File System Access 的浏览器，超过 200 MiB 时会提示换浏览器，避免一次拼接拖垮手机。
8. OCR/AI 翻译有识别精度、额度和网络失败的边界。原件保留、失败页明确标记和可重试，并不等于能承诺任何模糊照片都 100% 正确。
9. 第一次同步仍需下载书库现有内容，当前未实现无限文献规模的逐页懒加载。大量书籍的首次登录、弱网、微信真机和 AI 费用需要线上负载验收，不能用单元测试代替。
